# NyakoWordbook 桌面日语单词本：产品与实施规格

> 文档状态：细化设计基线，M1-A 正式数据底座已实现主要路径，M0 剩余平台验收并行保留，业务编辑和学习功能尚未实现。已验证能力见根目录 README 和实施决策记录；其他技术、算法、配额和性能数值仍为建议默认值，可经决策记录调整，不代表现有代码已经具备这些能力。

## 1. 产品定位

面向 Windows、macOS、Linux 的纯本地日语词汇管理与记忆工具，核心体验为高信息密度、完整键盘操作、可靠的本地数据交换。用户可以整理词库、导入自己的学习资料、离线复习，并随时导出内容和备份学习记录。

首版优先确保“导入 → 整理 → 复习 → 退出重开 → 备份恢复”的完整闭环。桌面小窗、测验和例句填空保留在产品范围内，按后续里程碑交付。

## 3. 建议技术基线

- 桌面壳：Tauri 2；系统能力和数据访问放在 Rust 后端。
- 界面：Vue 3 + TypeScript；使用虚拟列表和分页查询。组件库、构建工具及各依赖的具体版本在初始化时锁定。
- 存储：SQLite，开启外键和 WAL；串行写入，受控并发读取。
- 调度：固定版本的 FSRS 实现，保留算法版本和参数快照；实现选择通过验证后锁定。
- 文件交换：CSV、JSON、XLSX；后续增加以 Protobuf 为元数据载体的分块 `.jword` 格式。
- 本地优先：核心功能无需联网，不内置必须调用在线服务的词典、翻译或语音能力。

上述为降低实施分歧而给出的推荐，不是已有依赖。若改用 React 或 Qt，应先记录选择原因，并同步修订接口、窗口能力和验收方案。

## 4. 原稿细化后的关键约束

1. **词汇内容与学习状态分离**：同一词条可属于多个词库；内容更新不重置学习进度。首版每个词条仅有一张共享的认词卡。
2. **不把读音当唯一身份**：同形同音可能存在不同词条，`kanji+kana` 只能产生候选匹配，不能直接设为唯一主键。
3. **导入可以解释和恢复**：先预检、预览与冲突选择，再原子提交；默认保留已有进度和用户修改。
4. **调度可追溯**：每次有效打分产生事件并持久化调度结果；重复提交不增加两次记录。
5. **性能可测量**：GB 级文件仅承诺快速识别与预览，完整校验、解码、媒体落盘和数据库导入按吞吐量衡量，不承诺毫秒完成。
6. **跨平台能力有边界**：置顶、边缘吸附、任务栏隐藏等依赖系统和窗口管理器，必须提供可退回的普通窗口体验。
7. **本地不等于自动安全**：导入文件视为不可信输入，富文本、路径、资源大小、数据库迁移和备份恢复均需要校验。

## 5. 版本路线

| 阶段 | 用户可见结果 |
| --- | --- |
| M0 技术验证 | 三平台启动、SQLite/日文检索/FSRS/打包可行性得到验证 |
| M1 词库闭环 | 词库和词条管理、搜索、CSV/JSON 导入导出、备份恢复 |
| M2 学习闭环（MVP） | 认词复习、持久化调度、队列、撤销、键盘操作、基础统计 |
| M3 数据与桌面增强 | XLSX、`.jword`、媒体、受限富文本、沉浸与迷你窗口 |
| M4 练习增强 | 四选一测验、显式答案的例句填空、增强统计 |

MVP 指 M0—M2 全部通过验收，不能只以页面展示或编译成功视为完成。详细交付门槛见 [实施计划](specs/06-delivery-validation.md)。
