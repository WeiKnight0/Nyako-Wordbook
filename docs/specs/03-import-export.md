# 03 导入导出与文件协议

## 1. 格式与用途

| 格式 | 阶段 | 用途与限制 |
| --- | --- | --- |
| CSV | 不支持 | 当前导入与导出均拒绝，不提供兼容入口 |
| JSON v2 | M1，已实现 | 与十列词汇内容对应的结构化交换；不含个人调度记录 |
| XLSX | M1，已实现 | 单工作表、固定十列的词汇交换；格式或 Excel 单元格限制冲突时明确拒绝 |
| `.jword` | M3 | 可携带媒体的分块词库交换包 |
| `.nyakobak` | M1 | 完整备份；包含学习记录，走专用恢复流程 |

统一使用 `.jword` 作为自定义词库扩展名，不再并用 `.jdb`，避免与数据库文件和备份混淆。扩展名只作提示，实际必须检查内容。首版拒绝加密压缩包、`.xls`、`.xlsm` 和未知文件格式。

## 2. 导入流水线

1. **选择文件**：通过文件选择器或拖放取得只读文件句柄；目录拖入不递归扫描。多个文件逐个生成任务，不自动混合映射。
2. **识别与检查**：验证类型、版本、体积、可读性；计算文件摘要，记录源文件长度和修改时间。预览后文件发生变化必须重新预检。
3. **选择范围**：填写来源命名空间，选择现有词库或新词库；XLSX 固定表头和十列顺序，可查看工作表样本，不提供 CSV 编码/分隔符映射。
4. **全量校验**：解析到 staging，报告总行数、有效行、错误行和候选冲突；此阶段可取消且不修改业务库。
5. **冲突处理**：区分新建、相同、可更新、歧义；可按类别批量选策略，并逐条查看差异。
6. **确认**：用户明确选择“仅提交有效行”或返回修正；有错误时不默认跳过。展示将新建、更新、跳过、关联的数量，以及覆盖字段。
7. **提交**：重新检查来源摘要及目标 revision，冲突变化则返回预览；进入短期维护写入状态，事务合并词汇内容和词库成员关系。事务提交前取消必须完整回滚；进入提交点后显示不可取消。
8. **结果**：显示最终各类计数和任务 ID；提供用户主动保存的错误报告（行号、字段、原因）。成功提交后不能用“取消”撤销整个导入，需通过备份恢复或显式编辑处理。

目标必须满足 `有效行 + 错误行 = 数据行总数`；提交类别互斥，计数可核对。空行不算数据行；一个词有多条错误时行只计一次。

## 3. Excel 十列单表

### 3.1 XLSX（当前主入口）

当前只提供 Excel 与 JSON；旧 CSV 和旧版 JSON 均拒绝，不做兼容导入。

应用模板、导入和导出均只接受一个工作表，从 A1 起以第一行为固定表头，一行一个词条，不提供列映射。列顺序严格为：

| 列 | 表头 | 规则 |
| --- | --- | --- |
| A | 词条标识 | 可空；非空必须是文本；与来源标识组成稳定身份 |
| B | 写法 | 必填；纯假名词直接填写假名 |
| C | 假名 | 必填；用于推算音调拍数 |
| D | 释义 | 必填；单项直接填写；多义项在同格逐行写 `1. 第一义项`、`2. 第二义项` |
| E | 词性 | 可空；多个规范代码用 `|` 分隔；动词可写 `godan_verb|intransitive` 等活用类别加自／他属性 |
| F | 音调 | 可空；单个数字如 `0`，多个数字如 `0/1/2`，不另设拍数列；每个数字不得超出假名推算拍数 |
| G | JLPT | 可空；N1—N5 或 1—5 |
| H | 日文例句 | 可空；多条例句在同格逐行编号 `1. …`、`2. …` |
| I | 例句中文翻译 | 可空；多条例句按 H 列逐条编号对应，缺翻译保留空编号如 `2.` |
| J | 备注 | 可空；纯文本 |

动词活用类别为 `godan_verb`、`ichidan_verb`、`suru_verb` 或 `kuru_verb`；`intransitive`（自动词）和 `transitive`（他动词）是附加属性，二者最多一个，必须与动词活用类别同用。不确定时只填活用类别，不猜测自／他；同一写法兼有两种用法时分开建立词条。写法、假名、释义空白或音调不合规则逐行报错。编号从 1 连续、各占一行；单项不编号；例句中文翻译须与日文编号逐条对应，也可整列留空。日文例句默认关联第一义项，需要关联其他义项时在正文前写 `[义项2] `，不关联义项写 `[无关联] `；导出会保留这些标记。多值内容中原有换行或与编号/标记冲突时拒绝导出，不做含糊拆分。预览会显示前二十行；用户需填写稳定来源标识，重新导入同一来源保持词条标识不变。模板和导出预设写法、假名、日文例句列为 Yu Gothic 日文字体（包括后续新填单元格），其余列为 Microsoft YaHei 中文字体。标签和音调来源不属于新版词条模型；旧多表结构和旧版字段不会通过 JSON 绕行保存。旧多表文件不再作为导入格式。

工作表含公式即拒绝，要求先转换为值；不执行公式、宏、外部链接，日期/布尔/错误单元格拒绝。数字可用于普通文本或音调，词条标识要求文本。读取全部数据行（包括隐藏行）；合并单元格不填充，隐藏行筛选暂未实现，不声称按可见行导入。仅支持 `.xlsx`。文件最大 256MiB，归档展开最大 512MiB、十万条目、压缩比 100:1。单元格超过 Excel 32767 UTF-16 单元或表行数超限时拒绝导出并建议 JSON，不截断。

CSV 导入和导出均不再支持；表格交换统一使用 XLSX。

## 4. JSON 交换契约

顶层必须是对象，包含 `format`、`version`、`source_namespace`、`exported_at`、`words`。只接受 v2；词条不得带标签、媒体、音调来源、备注格式或个人卡片状态。

```json
{
  "format": "nyako-wordbook",
  "version": 2,
  "source_namespace": "nyako:export:00000000-0000-4000-8000-000000000001",
  "exported_at": "2026-11-01T00:00:00Z",
  "words": [
    {
      "external_id": "00000000-0000-4000-8000-000000000002",
      "kanji": "働く",
      "kana": "はたらく",
      "parts_of_speech": ["godan_verb", "intransitive"],
      "jlpt": "N4",
      "pitch_accents": [{"downstep": 0}],
      "senses": [{"meaning": "工作；劳动"}],
      "examples": [{"jp": "工場で働く。", "cn": "在工厂工作。", "sense_index": 0}],
      "note": "注意助词搭配。"
    }
  ]
}
```

例句的 `sense_index` 可选，从零开始对应 `senses` 的顺序；省略或 null 表示不关联特定义项，越界报错。音调数组中每项只包含数字 `downstep`，范围由假名拍数校验。

导出命名空间应为本地安装创建并持久保存的随机导出源 ID，不能每次导出随机生成；同一词条在该命名空间下保持 external_id 稳定。导入第三方来源后的再次导出使用本地导出身份，不伪装成原作者来源。

读入时拒绝重复 JSON 对象键、超深嵌套和非 v2 格式。字段白名单校验拒绝旧字段及未知字段，不静默丢弃；`senses` 至少一项，写法、假名、释义均不可空。

## 5. 身份匹配与更新规则

`kanji+kana` 不建立数据库唯一约束。按以下顺序查找：

1. 有 `source_namespace + external_id` 且存在映射：匹配唯一词条，比较导入字段与已有内容。
2. 无来源映射：以归一化写法和读音找候选。NFC、首尾空白作为身份归一化；片假名/平假名等价仅用于搜索，不直接用于身份合并。
3. 候选内容完全相同：可以选择复用并增加词库成员关系；多个相同候选仍需指定目标。
4. 候选不同或多候选：必须让用户选择复用、创建独立词条或跳过。默认不覆盖。

提供“保留现有”“仅填补空字段”“以导入内容替换选定字段”三种策略；集合字段默认不做不可解释的逐元素合并。选择覆盖时展示整个义项/例句集合替换的效果。未映射的列不参与覆盖，空值不等于清空，清空必须单独确认。

所有策略均保留 cards 和 review_events，不改变暂停状态或到期时间。首次成功映射后记录 source_links；相同包再次导入复用映射和内容摘要，不重复新增词条/标签/成员关系。同一文件出现相同外部身份的多行直接报冲突，不采用“最后一行赢”。

## 6. `.jword` V1 分块协议（M3）

目标为顺序读写、快速识别和有限预览、受限内存占用、逐块校验；不是直接映射成 SQLite，也不承诺 GB 级全量解析毫秒完成。mmap 仅作为验证后的优化选项，基础实现可使用流式 I/O。

### 6.1 固定头：64 字节，小端序

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 8 | Magic：ASCII `NYAKOJWD` |
| 8 | 2 | 主版本：1 |
| 10 | 2 | 次版本：0 |
| 12 | 4 | flags：V1 为 0，未知位拒绝 |
| 16 | 8 | manifest_offset：V1 固定 64 |
| 24 | 8 | manifest_length：上限 16 MiB |
| 32 | 32 | manifest 原始字节 SHA-256 |

manifest 为 Protobuf，包含包 ID、来源命名空间、创建时间、记录数、媒体总量、预览样本（最多 20 条）和块描述列表。各块描述包含类型、绝对偏移、存储长度、原始长度、SHA-256 和记录数。所有整数做溢出和边界检查；偏移不得覆盖头和清单，不允许块重叠或尾部未声明数据。

V1 块类型：`WORD_BATCH`、`MEDIA`。词条块保存长度前缀的 Protobuf WordRecord 序列，长度前缀使用 unsigned varint32；单条消息上限 1 MiB，每词条块目标 4 MiB、硬上限 8 MiB。媒体块每块一个完整附件，不把所有音频装入单个巨型消息。

V1 不压缩、不加密。块散列覆盖实际存储字节，文件总长度由最大块末端决定。媒体描述记录 SHA-256、受控 MIME、长度和逻辑资源 ID；词条只引用逻辑资源 ID，不携带操作系统路径。Protobuf 字段编号、枚举数值、保留字段与 `.proto` 文件是 M3 协议冻结交付物，冻结前禁止对外宣称稳定互通。

解析时先验证固定头与清单摘要，显示标明“尚未完整校验”的预览；导入前逐块校验全部内容、资源引用、记录数和 ID 唯一性。散列用于完整性检查，不代表可信发布者签名。

## 7. 默认资源限制与输入安全

以下为建议保护默认值，用户可在受控高级设置中提高体积/数量限制；格式结构限制不能绕过：

| 限制 | 默认值 |
| --- | --- |
| CSV/JSON/XLSX 文件体积 | 256 MiB |
| `.jword` 文件体积 | 4 GiB |
| 单次导入词条数 | 500,000 |
| 单个文本字段 UTF-8 长度 | 64 KiB；单词条合计 1 MiB |
| 单媒体体积 | 32 MiB |
| 单包媒体总量 | 3 GiB |
| JSON/Protobuf 逻辑嵌套深度 | 16 |
| XLSX/备份解包总量 | 8 GiB；单条目上限按媒体或数据库类型约束 |
| ZIP 条目数量/压缩比 | 100,000 / 100:1 |

所有压缩包解包拒绝绝对路径、盘符、`..`、符号链接、重复规范化路径及越出 staging 的条目。先估算目标、暂存、备份所需空间，空间不足在写入前报告；估算不能替代写入期间的磁盘满处理。

音频仅接受已验证的 MP3/WAV/Ogg，图片仅 PNG/JPEG/WebP；检查签名、尺寸和解码结果，不因扩展名信任内容，不支持 SVG/可执行附件。解码器实际可用格式需在三平台验证；失败显示附件错误，不能导致整个应用崩溃。

## 8. 导出与取消

导出固定一个数据库读取快照，以保证词条和关联一致；媒体垃圾回收在任务结束前禁止移除被引用文件。写目标同目录临时文件，完整写出并校验后原子重命名；覆盖已有文件必须确认。失败或取消清理本任务临时文件，原目标保持可用。

交换包只导出用户选中的词汇内容、标签和可选媒体；完整学习记录仅在备份中携带。JSON 与 `.jword` 应满足导出后导入空数据目录的词汇语义等价，不要求本地数据库 ID 和时间戳相同。
