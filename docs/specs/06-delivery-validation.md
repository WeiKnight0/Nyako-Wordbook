# 06 实施计划与验收

> 当前正式库使用根目录下的 `data/main.sqlite3`，旧版数据删除，不使用 `v3/`；词汇交换只支持十列 XLSX 和 JSON v2。下面按日期记录的旧标签、CSV、旧 schema 和性能验收是当时版本的事实，不代表新版本仍具备这些功能或已达到相同性能目标。

## 1. 交付原则

当前已实现 M1-B 词汇管理主体，正在进行交互收尾和正式数据验收，M0 跨平台验收仍有剩余项；已经验证的命令、依赖和结果见第 8 节及根目录 README。下列门槛仍是各阶段完整验收目标，须在实际发行构建上逐项验证，不能把局部技术探针通过视为整阶段完成。

每个里程碑交付可运行增量、所需数据库迁移、必要自动化测试和人工验收结果。测试命令在初始化后按实际工具链确定并写入项目使用说明；不要预设当前目录已有 npm/Cargo 工程。

## 4. 自动化验证分层

工程初始化即建立与所选工具链一致的测试设施。测试重点为可观察业务行为和持久化约束，而不是为每个视图函数复制实现。

- **规则单元测试**：字段归一化、拍数与音调范围、CSV 引号、身份匹配、过滤语义、时间边界、调度参考向量。
- **数据库集成测试**：真实临时 SQLite，启用生产同款 PRAGMA；迁移、外键、乐观锁、导入提交/回滚、重复事件、撤销和统计。
- **文件集成测试**：流式输入、文件变更、损坏包、媒体引用、取消、磁盘写失败注入、备份恢复；M3 增加越界块/压缩炸弹/路径穿越样本。
- **端到端测试**：实际桌面命令和持久化文件完成导入、编辑、评分、重启与恢复；自动化受限的平台人工补齐，不能仅验证前端 mock。
- **发行冒烟**：从安装包启动，验证资源路径、数据权限、单实例、拖放和卸载后数据保留策略。

## 6. 性能验收口径

### 环境与数据

参考机建议为 4 核 CPU、16 GiB 内存、本地 SSD；发行构建、非调试、无杀毒排除特例。记录 CPU、内存、系统、WebView、磁盘、应用与依赖版本。Windows 为主要基准平台，macOS/Linux 同样执行功能验收并记录性能差异。

标准数据集：20 万词、每词 2 义项/2 例句/3 标签；每词一张卡，100 万评分事件；另备无媒体小包与含约 1 GiB 媒体包。数据使用合成内容，不能复制用户私人词库。冷启动为进程未运行，热查询为连接/索引已就绪；文件系统缓存状态单独记录。

下表为建议目标，M0/M1 基准后可以有依据地修订；未测量前不宣称满足。

| 操作 | 目标 | 测量方式 |
| --- | --- | --- |
| 冷启动至列表可交互 | P95 ≤ 3 秒 | 20 次启动，从进程创建到首批可操作行 |
| 已启动打开 100 行列表 | P95 ≤ 200 ms | 至少 100 次，后端查询+IPC+渲染 |
| 三字符以上搜索 | P95 ≤ 300 ms | 至少 100 组中日混合查询；不含 200 ms 防抖 |
| 一至二字符搜索 | P95 ≤ 800 ms | 覆盖低选择性关键词，不只测无结果词 |
| 评分至下一卡可交互 | P95 ≤ 150 ms | 至少 500 次真实事务，含持久化 |
| 列表滚动 | 60 Hz 参考屏连续 30 秒，无超过 100 ms 主线程长阻塞 | 报告帧时间分布；不承诺所有平台始终 60 FPS |
| 20 万词列表内存增量 | ≤ 300 MiB | 相对空库空闲基线，包含前端与后端，不含导入 |
| 10 万简单 CSV 词条首次导入 | ≤ 60 秒 | 从确认到提交成功，含索引，不含人工映射 |
| 1 GiB `.jword` 头与样本预览（M3） | P95 ≤ 1 秒 | 只读取固定头和清单，标注未全量验证 |
| 1 GiB 包完整验证与导入（M3） | ≥ 20 MiB/s，额外内存 ≤ 512 MiB | 包含校验、媒体落盘、数据库提交，分阶段报告 |

导入性能不等于界面首屏速度。基准必须报告数据形状、处理数量、实际字节与峰值内存，不能只以 mmap 打开耗时代表完成导入。

## 7. 发布门槛与故障优先级

MVP 发布前必须完成：类型/静态检查、发行构建、业务与数据库测试、E01—E18、三平台安装启动、键盘/输入法验收、备份恢复和主要性能基准。首次安装、跨版本迁移、数据目录无写权限、单实例二次启动都需覆盖。

阻断发布的问题：数据丢失、无法恢复、静默覆盖、重复评分、错误调度、核心流程崩溃、不可信文件导致越权读写。搜索慢、帧率不足等不应伪装成已通过指标；记录偏差、影响和修复方案，若需降标由产品明确接受后更新规格。

更新包、签名和分发渠道在正式发布前确定；初期可手动安装升级，不要求内置自动更新。卸载默认保留用户数据，删除数据须是用户明确选择。支持回滚应用版本的前提是数据库 schema 兼容；否则必须使用对应备份恢复，不直接用旧程序打开新库。
